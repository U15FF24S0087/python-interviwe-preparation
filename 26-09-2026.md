# Python Interview Preparation

## Questions and Answers

### 1. What is Python?

Python is a high-level, general-purpose programming language. Its readable syntax and extensive standard library make it useful for scripting, web development, automation, data analysis, artificial intelligence, scientific computing, and many other tasks.

### 2. What are Python's main features?

- **Readable syntax:** Code is designed to be relatively easy to read and write.
- **High-level:** Python handles many low-level details, such as memory management, for the programmer.
- **Dynamically typed:** A variable name can refer to values of different types at different times; types belong to values, not variable declarations.
- **Multi-paradigm:** Python supports procedural, object-oriented, and functional programming styles.
- **Portable:** The same source code often runs on Windows, macOS, and Linux, subject to platform-specific dependencies.
- **Large ecosystem:** The standard library and third-party packages cover a wide range of tasks.
- **Interactive:** The Python interpreter can run commands interactively, which is useful for exploration and debugging.
- **Extensible and embeddable:** Python can work with code written in other languages and can be embedded in other applications.

### 3. What are the advantages and disadvantages of Python?

**Advantages**

- Its syntax is approachable and usually concise.
- It supports rapid development and has a large package ecosystem.
- It works across major operating systems.
- It is widely used in automation, web services, data science, and machine learning.
- It includes a substantial standard library.

**Disadvantages**

- For many CPU-heavy tasks, standard Python implementations are slower than compiled languages such as C, C++, or Rust.
- Dynamic typing can allow some mistakes to surface only when code runs; tests and optional type checking help reduce this risk.
- The Global Interpreter Lock (GIL) in the standard CPython build limits parallel execution of Python bytecode across threads for CPU-bound work. Processes, native extensions, or other Python implementations can be appropriate alternatives.
- Python applications can use more memory than equivalent low-level implementations.
- Packaging and dependency management can require care, especially across operating systems or projects.

### 4. What Python versions are there?

Python 3 is the current major version. Releases follow a `major.minor.micro` pattern, for example `3.14.1`: `3` is the major version, `14` is the minor version, and `1` is the bug-fix (micro) version. New minor versions add features; micro releases primarily contain fixes and security updates. Python 2 reached end of life in 2020 and should not be chosen for new projects.

Different Python 3 minor versions can be in different lifecycle stages: pre-release, bug-fix, security-only, or end-of-life. Check the official status page before choosing a version for a project: [Python Developer's Guide: Status of Python versions](https://devguide.python.org/versions/).

### 5. What is the most stable Python version?

There is no separate Python “LTS” release. For a new project, the usual choice is the latest final Python 3 release supported by the libraries and deployment environment you need. For an existing production system, use a supported release that your dependencies have been tested against, and keep it updated with the latest patch release in that series. Avoid alpha, beta, and release-candidate builds for ordinary production use.

The exact latest release changes over time. Check [python.org downloads](https://www.python.org/downloads/) and the version lifecycle page before installing. You can check the interpreter installed on your machine with `python --version` or `python3 --version`.

### 6. What tools are used to manage Python dependencies and develop Python software?

- **`pip`:** Installs packages from the Python Package Index (PyPI), commonly using a `requirements.txt` file.
- **`venv`:** Creates an isolated virtual environment for a project; it is included with Python.
- **`uv`:** A fast tool for managing Python packages, environments, and project workflows.
- **Poetry:** Manages project dependencies, virtual environments, and package publishing.
- **Conda / Miniconda:** Manages environments and packages, including non-Python libraries; common in scientific computing.
- **IDEs and editors:** Visual Studio Code, PyCharm, and JupyterLab provide editing, debugging, and other development features.
- **Quality tools:** `pytest` for testing, Ruff for linting and formatting, and mypy or Pyright for optional static type checking.

For a small project, a built-in `venv` plus `pip` is a straightforward starting point. Avoid installing every project's packages into the system-wide Python environment.

### 7. What file extension is used for Python source files?

Python source files normally use the `.py` extension, for example `app.py`. Stub files use `.pyi`, compiled bytecode files commonly use `.pyc`, and Jupyter notebooks use `.ipynb`.

### 11. How does Python work internally?

This depends on the Python implementation. In the common implementation, CPython, the interpreter broadly:

1. Reads source code and parses it according to Python's grammar.
2. Compiles it to Python bytecode, often caching compiled modules as `.pyc` files.
3. Executes the bytecode in the CPython virtual machine.
4. Uses runtime objects to represent values, and manages memory primarily with reference counting and a cyclic garbage collector.

This is a useful mental model, not a requirement that every Python implementation work identically. For example, PyPy uses a just-in-time compiler, while other implementations may use different execution strategies.

### 12. What is Python's architecture?

At a high level, a CPython program passes through these layers:

1. **Source code:** The `.py` files written by the programmer.
2. **Parser and compiler:** Check syntax and produce code objects containing bytecode.
3. **Virtual machine:** Executes bytecode and coordinates operations at runtime.
4. **Runtime object system:** Represents integers, strings, functions, classes, and other values.
5. **Memory management:** Allocates and releases objects, using reference counts and cyclic garbage collection in CPython.
6. **Standard library and extensions:** Provide built-in modules and interfaces to native code and operating-system services.

This describes CPython, the reference implementation most people install from python.org. Python is a language specification as well as a family of implementations, so details can differ between implementations.

### 13. What is indentation in Python, and why does Python use it instead of braces?

Indentation is the whitespace at the start of a line. In Python, consistent indentation marks a block of code, such as the body of a function, loop, or conditional. A colon introduces the block, and the indented statements belong to it:

```python
if temperature > 25:
	print("It is warm")
else:
	print("It is not warm")
```

Many languages use braces to mark blocks and semicolons to end statements. Python uses indentation as part of its syntax to make block structure visible and reduce punctuation. Use four spaces per indentation level, avoid mixing tabs and spaces, and keep indentation consistent. A colon does not replace a semicolon; it introduces a suite such as a function, class, conditional, or loop body.

### 15. What are variables in Python, and how do they differ from variables in other languages?

A variable is a name bound to an object. Assignment creates or updates that binding:

```python
language = "Python"
year = 1991
```

In Python, you do not normally declare a variable's type in advance. The object has a type, and a name can later be rebound to an object of another type:

```python
value = 10
value = "ten"
```

This is allowed, though reusing a name for unrelated types can make code harder to understand. Languages such as Java or C# commonly require a declared or inferred static type for each variable. Python also supports optional type annotations, which tools can check without changing the basic runtime model:

```python
count: int = 10
```

### 16. What are Python data types, and how do they compare with other languages?

A data type describes the kind of value an object represents and the operations available for it. Common built-in Python types include:

- **Numbers:** `int`, `float`, and `complex`; `bool` represents `True` or `False` and is a subclass of `int`.
- **Text:** `str`, an immutable Unicode string.
- **Sequences:** `list` (mutable), `tuple` (immutable), and `range`.
- **Mappings:** `dict`, a mutable key-value mapping.
- **Sets:** `set` (mutable) and `frozenset` (immutable).
- **Binary data:** `bytes` (immutable) and `bytearray` (mutable).
- **No value:** `None`, whose type is `NoneType`.

Python is dynamically typed: types are associated with objects and checked at runtime. This contrasts with statically typed languages, where the compiler checks declared or inferred types before the program runs. Python uses duck typing: code often relies on the operations an object supports rather than requiring a particular declared class. Type hints can help editors and static-analysis tools catch mistakes, but they are not generally enforced by the Python runtime.

### 17. What are functions in Python? Explain the syntax with an example.

A function is a reusable block of code. It can accept input through parameters, perform work, and optionally return a result. Define a function with `def`; use `return` to send a result back to the caller:

```python
def calculate_total(price: float, quantity: int = 1) -> float:
	"""Return the price multiplied by the quantity."""
	return price * quantity


total = calculate_total(4.50, quantity=3)
print(total)  # 13.5
```

Here, `price` and `quantity` are parameters. `quantity` has a default value, so the caller may omit it. The call passes `4.50` positionally and `3` by keyword. The annotations describe expected types and the return type for readers and tools; Python does not enforce them automatically. A function without an explicit `return` returns `None`.

Python functions are objects: they can be assigned to names, passed to other functions, and returned from functions. This supports callbacks, decorators, and higher-order programming.

### 18. What types of functions are there in Python?

Common categories include:

- **Built-in functions:** Provided by Python, such as `len()`, `print()`, and `sum()`.
- **User-defined functions:** Created with `def`.
- **Anonymous functions:** Small lambda expressions created with `lambda`; they contain one expression and are most useful for short callbacks or sort keys.
- **Methods:** Functions associated with an object or class, such as `"hello".upper()` or `list.append()`.
- **Generator functions:** Use `yield` to produce values lazily, one at a time.
- **Coroutine functions:** Use `async def` and are designed for asynchronous operations, often with `await`.
- **Recursive functions:** Call themselves, usually with a base case that stops the recursion.

These categories can overlap: for example, a user-defined method can also be a generator function.

### 19. What are parameters and arguments in Python?

**Parameters** are the names listed in a function definition. **Arguments** are the actual values supplied when calling that function.

```python
def describe(name, greeting="Hello"):
	return f"{greeting}, {name}!"


describe("Ada")                    # name is the parameter; "Ada" is an argument
describe(name="Ada", greeting="Hi")  # keyword arguments
```

Common parameter and argument forms include:

- **Positional:** Matched by position, as in `describe("Ada")`.
- **Keyword:** Matched by name, as in `describe(name="Ada")`.
- **Default:** A parameter value used when the caller omits that argument, as with `greeting="Hello"`.
- **Variable positional (`*args`):** Collects extra positional arguments into a tuple.
- **Variable keyword (`**kwargs`):** Collects extra keyword arguments into a dictionary.
- **Keyword-only:** Must be passed by name when placed after `*` or `*args` in the definition.
- **Positional-only:** Must be passed by position when marked before `/` in the definition.

```python
def report(title, /, *items, uppercase=False, **details):
	"""Example of positional-only, variadic, and keyword-only parameters."""
	label = title.upper() if uppercase else title
	return label, items, details


report("Summary", "one", "two", uppercase=True, owner="Ada")
```

In this example, `title` is positional-only, `items` gathers extra positional arguments, `uppercase` is keyword-only, and `details` gathers additional keyword arguments.
